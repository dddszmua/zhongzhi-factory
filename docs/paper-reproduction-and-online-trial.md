# 论文 / 专利复现与在线试用设计

本设计基于 2026-09-29 工作区中的 zhongzhi-factory、ioeb_backend 和 Micro-Agent 源码检查。以下第一节记录最初发现的问题，后续章节保留完整目标设计。当前交付状态见下表；本地未连接完整部署环境进行端到端验证。

## 当前交付状态

- 已接通创建页的论文/专利复现模式，支持主资料与补充资料 PDF/DOCX、受限学术/专利网址、重点页码与参数说明。主资料可预览提取文本，用户需确认关键公式和参数。无法提取文本、旧 DOC 和超长资料会明确拦截或提示。
- 已将生成结果的 Python 源码、运行规范、合成样例提交后端；参考原文件保存于模型目录，记录名称、大小和 SHA-256。源码与规范校验、受限容器样例运行决定 ready 状态。作者还可填写原文计算样例及页码，平台实际运行并按数值容差对照；复现模式需对照通过才能获目录批准。
- 已提供作者的运行规范配置、合成样例验证和私有试用；公开目录由审核状态控制，公开运行需登录、审核通过、作者开启试用，付费模型还需购买。前端按规范生成输入表单，后端校验字段、范围、单位及版本。
- 已提供审核队列页面 `/supplier/review`，仅有后端管理员权限的用户可读取和审批。普通作者在 `/supplier/trial` 管理运行规范与公开试用开关。
- 尚未实现扫描件 OCR、公式定位与逐项出处绑定、自动抽取原文对照样例、训练流水线、权重上传、GPU/依赖环境构建及独立临床验证。当前 ready 仅表示平台合成样例能够运行；手工提交的原文对照通过只证明该用例在设定误差内一致，不表示论文整体效果或临床效果已复现。

## 一、当前实现与需要接通的位置

### 1. 资料驱动生成：Agent 有入口，当前前端未接通

- `src/pages/supplier/CreatePage.tsx` 的生成分支只提交文字描述、行业、场景和固定的 `classification` 类别。源码上传分支支持 Python 和部分数据文件，并不是用于生成前上传论文。
- `Micro-Agent/api/routes/agent.py` 的 `/api/agent/aml_auto_generate` 已接收 `file`、`dataset_file`、`reference_files`、`reference_urls`、`reference_notes`、`domain`、`clinical_task` 和 `generation_mode`。
- Agent 以 `domain=clinical` 启用临床生成提示与知识来源，以 `generation_mode=reproduce` 表示复现。服务目录仍使用 `domain=health`。前端必须显式映射，不能只提交行业名称。
- 现有文档处理以文本提取为主。主文档进入提示的内容被截到前 3000 字符，单份参考资料默认前 4000 字符，合并参考资料进入提示时最多 6000 字符。方法、公式、附录可能根本没有进入生成上下文；不能据此宣称完整复现。
- 文档提取失败目前可能仅记录日志并返回空文本。旧 `.doc` 扩展名虽然被接收，实际使用的是 DOCX 读取方式。应明确拒绝不支持格式，或先完成可靠转换。
- 当前保留了名称以 `wst` 开头时直接生成固定金融演示代码的隐藏分支，且返回写死的测试通过信息。正式生成流程必须移除此分支；测试夹具只保留在明确隔离的开发环境中。

### 2. 在线试用：存在请求功能，但生成到运行没有闭环

- 详情页的 `trialInvoke` 使用浏览器 `fetch` 直接访问配置地址。外部服务已经运行、网络可达且允许跨域时，可以真实发出请求；仅有 Python 源码不能因此运行。
- 试用配置页的 `allowTrial` 只保存在组件状态中，保存地址时没有提交，也没有服务端执行权限开关。
- `mapServiceToProduct` 根据部署状态或是否填写 URL 判断“可试用”，没有读取实际运行验证状态。
- 本地后端 `ServiceService.deploy_service` 目前通过等待后修改状态模拟部署，不能证明模型进程或接口已经启动。
- 后端另有 `/api/services/{id}/algorithm-artifact` 和 `/api/services/{id}/algorithm-run`（同时提供 clinical 别名）。前者读取运行规范，后者检查登录与访问权限、ready 状态、参数和源码哈希，再在受限 Docker 容器中运行 `main_process`。这是应优先接入的能力。
- 生成提示已要求返回 `algorithm_spec` 和 `smoke_input`，上传接口也支持这两个字段；当前前端结果类型和保存流程没有承接并提交它们，导致后端记录为待配置。
- 当前运行器主要支持单个 Python 文件、标量命名参数和 JSON 输出；默认镜像没有专门准备模型依赖、权重或 GPU，不应标记为支持任意机器学习模型。
- 当前浏览器 CSV 评估页分析的是已有标签与预测分数，不会调用模型产生预测；JSON 批量用例页比较返回内容，也不等于论文复现或临床有效性验证。

## 二、产品流程：先确定复现目标，再生成

建议创建页首先选择“依据资料复现”或“按需求开发”。上传源码作为已有实现的导入入口保留。

“依据资料复现”依次完成：

1. **提交资料**：上传主论文或专利、补充材料、参数表，可附已有代码和权重。分别标明资料角色、文档版本、题名、作者或公开编号；允许填写关注页码、公式号和实施例。
2. **选择复现范围**：完整方法、某个子算法、固定公式 / 评分、已训练模型推理、重新训练并复现实验。不能把这些目标混为一次泛化的“生成模型”。
3. **核对实现说明**：平台提出结构化草案，用户检查公式、参数、单位、预处理、缺失数据规则、适用范围和预期输出。每项附资料出处；不确定项单独列出。
4. **生成与验证**：按已确认说明生成代码、运行规范、固定依赖和验证用例，执行真实测试，保留失败与修订记录。
5. **私有试用**：作者可以直接运行自己的已验证版本。通过目录审核后才允许符合权限的其他用户试用。

对于一个简单公式，页面应快速完成“选择公式 → 核对变量与参数 → 计算样例”。完整研究模型再展开训练、数据划分、依赖与权重设置，避免所有任务都经过冗长训练表单。

### 不同复现范围对应不同交付

- **公式或规则算法**：原公式、符号与单位映射、参数出处、计算函数、数值对照用例和输入表单。
- **论文中的训练方法**：网络或模型结构、损失函数、预处理、超参数、随机种子和训练入口；没有数据或训练产物时交付可复现的开发工程，明确未训练。
- **已有模型推理**：同时固定预处理、模型结构、参数权重和依赖。缺少权重时标记“待补权重”，不得使用随机权重输出冒充论文模型结果。
- **实验结果复现**：需要确定的数据版本、划分和评价协议，产出实际运行指标及与原文报告的差异。代码成功执行不意味着复现了论文中的性能。
- **专利中的算法**：让用户选择具体实施例或算法步骤，并区分说明书中的可执行细节与概括性描述。缺少公式、参数或样例时列为缺项，不由系统猜测补齐。

“严格复现”模式不得自行替换公式或调参。“按需求改造”允许改变方法，但必须保留原版并说明每一处变化。

## 三、解析与追溯

### 资料处理

- 保存受项目权限保护的原文件、文件哈希和解析版本；按页与章节建立索引。
- 文本型 PDF 解析正文、表格和公式；扫描件进入 OCR 流程。给用户展示识别后的公式和对应原页面区域，便于核对上下标、负号、希腊字母和分式。
- 对空提取、低置信度公式、不完整表格以及文档之间的冲突显示明确提示。解析失败不能作为“已有资料”继续完成自动复现。
- 方法、参数表、补充材料、所选公式及定义是必查内容。检索用于补充相关上下文，不能用“只取文档开头”代替阅读目标方法。
- 每个核心公式、参数和处理规则关联 `documentId + page + section/equation + excerpt`；用户补充的数值标记为用户提供。
- 上传资料是参考数据，不具有改变平台权限或生成执行规则的权力。代码附件先作为资料解析，执行只能进入隔离运行环境。

### 用户确认的实现说明

至少记录：目标类型、输入字段、数学符号、单位、有效范围、必填与缺失策略、公式及运算顺序、固定参数及出处、输出含义、适用人群、已知限制、预处理步骤、依赖与权重需求、待确认问题。

预测时点与预测时间范围必须分开保存。目前创建页将 `horizon` 当作“使用时点”加入生成描述，应在接入时修正。

原始资料 → 确认后的实现说明 → 源码与环境 → 验证结果 → 可运行版本应有连续的版本关系。资料、参数、代码或权重发生变化后创建新版本并重新验证。

## 四、复现验证与交付状态

验证用例优先来自原文示例、参数表、作者参考实现或用户给出的核对结果。分别记录来源、输入、预期输出、实际输出和误差容忍度。浮点计算采用明确的绝对 / 相对误差，而不是一律比较 JSON 是否完全相同。

平台自行构造的边界用例用于检查实现健壮性；Agent 根据同一份生成代码推导出来的期望值，不能作为独立复现证据。

至少区分以下结论：

- 资料已解析，关键缺项仍待确认。
- 代码已生成，但运行规范、依赖或权重待配置。
- 平台样例运行已通过。
- 有出处的公式 / 参数对照用例通过。
- 在指定数据和协议下完成实验复现。
- 已完成独立临床数据评估。

状态和报告必须来自保存的真实运行记录。资料未给出结果、数据不可用或参数不完整时，应说明无法验证的内容，不输出虚构的“测试通过”或准确率。

## 五、在线试用的推荐实现

### 默认使用统一的后端执行入口

浏览器先按模型 ID 获取运行规范，再生成带单位、范围、必填提示和合成示例的表单。用户提交后，后端验证身份、项目权限、版本、试用开关和输入，通过后把任务交给受控执行器，返回结构化结果、模型版本、运行编号、耗时和必要提示。

普通使用者不需要配置 URL 或了解 Docker。作者在工作台查看依赖和验证失败原因；公开详情只展示已通过运行验证且被允许试用的版本。

### 复用现有接口，补齐断点

1. `AmlGenerateResult` 增加 `algorithm_spec`、`smoke_input` 及来源、验证报告的类型。前端保存结果时将规范和样例提交至现有上传接口。
2. 用 `algorithm-artifact` 取得规范和状态，新增按规范生成的试用表单；通过登录客户端调用 `algorithm-run`，提交 `{ inputs, version }`。当前后端尚未接收并核对客户端指定版本，需同步补齐。
3. 以服务端的运行状态与权限决定“可试用”，不再使用是否填写 URL 或通用部署状态作为依据。当前 `onlineUsage` 已提供部分状态，但仍须补充临床目录和试用授权条件。
4. 试用开关持久化为服务端字段。作者调试与公开试用分别授权：作者可测试私有版本，其他用户需满足目录审核和项目授权。关闭公开试用后直接请求运行接口也应被拒绝。
5. 已上传但待配置的模型需要补录规范、样例与重新验证的入口，避免只能反复创建新服务。
6. 输入规则补充最小值、最大值、单位和缺失处理；后端也必须校验。输出补充格式校验、有限数值检查、大小限制和错误结构。

### 分两类运行

- **轻量公式和算法**：按次调用受限容器，限制运行时间、内存、CPU、输出大小和网络访问。首版先支持结构化标量输入与 JSON 输出。
- **依赖模型权重或耗时较长的任务**：上传并固定权重、预处理代码和依赖镜像，预加载模型或使用任务队列。界面展示排队、运行、成功、失败、超时和取消状态；文件上传及 GPU 能力单独扩展。

现有容器运行器可作为轻量执行基础，但仍需补齐镜像依赖准备、日志与输出上限、容器超时清理和执行记录。当前只限制了 Docker 客户端等待时间，还应明确确保超时后的实际容器被停止。

对医院已有接口可增加受管理的服务适配方式。外部地址由后端按项目配置、限制目标并管理凭据，浏览器统一按模型 ID 发起调用。不能把任意 URL 直接变成后端可请求的地址。

## 六、开发顺序与验收条件

### 第一轮：跑通一个有原文对照的计算算法

接通资料上传、`domain=clinical`、`generation_mode=reproduce`；提供公式与参数核对页；移除隐藏演示生成；保存真实运行规范及样例；接通现有运行接口与作者私有试用；持久化并执行试用权限。

验收：用户提供一份含明确公式、参数和对照结果的资料，核对后生成代码；平台实际运行对照用例；作者无需配置服务地址即可在表单输入数据并得到与原文一致、在规定误差内的结果。缺参、解析失败、运行环境不可用时都有明确状态。

### 第二轮：提高资料复现可靠性

补齐扫描件与公式识别、页码追溯、多文档冲突确认、独立对照测试、资料 / 参数 / 源码版本管理和验证报告下载。

验收：核心公式位于文档后半部分或附录时仍可定位；错误单位和非法输入被拦截；结果可追溯到资料、参数与代码版本；修改代码后旧验证状态失效。

### 第三轮：支持训练模型和批量推理

支持锁定依赖、权重资产、异步任务、CSV 字段映射、批量输出和评估页衔接。缺少训练数据或权重的任务明确停留在相应待配置状态。

验收：批量任务按同一锁定版本产生可下载预测结果，评估页可使用这些真实预测；运行失败、取消与超时可追踪；源码、资料和数据访问受服务端权限限制。

这一顺序可先把“资料中的一个明确算法 → 可核对实现 → 真正在线运行”做实，再扩展到复杂论文模型。
